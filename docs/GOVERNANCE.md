# P390 治理层规划 —— 做「人的权威节点」

> 目标：把 P390 从「人类伪装成模型的转发器」（接入层）上移为「人机分工与治理的调度中枢」（治理层）。上游 Agent 调用 P390 不只获得一个「人工模型端点」，而是获得一整套**人类治理协议**：数据不出网关、操作有人审批、产出有人担责、全程可审计。

---

## 一、定位澄清（双层产品形态）

| 层 | 形态 | 作用 |
|---|---|---|
| **互联网 DEMO** | `USER_REGISTER_MODE=open` 免费注册即用 | **演示获客**：用户第一时间看到「接入、分级、审批、工作台」演示才有机会使用 → 转化漏斗第一环 |
| **私有部署** | 内部/客户环境，`audit` 审核开户 + 治理能力 | **治理中枢**：完整分级策略、审批链、合规留痕 |

两者不冲突：DEMO 是「展示能力」的窗口，私有部署是「交付治理」的产品本体。规划以治理层为主体，DEMO 保持轻量展示。

---

## 二、「人的权威节点」四大支柱：现状 → 治理目标

| 支柱 | 现状（代码实况） | 治理层目标 |
|---|---|---|
| **分级是人的边界** | `tasks.category` 硬编码 3 类（general/confidential/ops）；上游显式传；非法回退 general | **策略规则引擎**：分类规则可配置（关键字/来源/项目）；显式 category 只能升级不能降级（**合规白名单锁死**）；AI 能力评估可动态漂移 general 边界 |
| **审批是人的权力** | 单级 `pending→approved\|rejected`；/v1 同步挂起等 5 分钟；无审批策略/审计 | **审批链治理**：异步化（返 `approval_id` + 回查）；审批人策略（指定/轮值）；审批超时升级；审批全链留痕 |
| **质量是人的标准** | `qualityCheck` 长度+占位词；运维类文档承认「建议人工验收」 | **质量治理**：验收标准分类（内容类自动校验 / 运维类人工验收单）；一次通过率统计；打回原因结构化并回馈 |
| **留痕是人的证据** | task_logs / request_logs 全量记录 | **合规审计**：日志哈希链防篡改（可证明）；单任务治理链路一键导出（创建→分级→审批→质量→交付） |

## 三、分阶段规划

### 阶段一 · 治理地基（1-3 月）——补命门 + 机制化

| # | 动作 | 落地要点 |
|---|---|---|
| 1 | **审批流异步化** | `/v1/approvals` 创建后立即返 `approval_id`，新增 `GET /v1/approvals/:id` 回查；与任务 task_id 契约统一，消除 5 分钟挂起矛盾 |
| 2 | **分级策略引擎 v1** | 分类规则表 `task_rules`（关键字/来源/项目 → category，权重序）；上游显式 category 高优先；**confidential/ops 不可被降级**（白名单锁死）；匹配命中记录 `rule_id` 进任务（分级理由可查） |
| 3 | **质量验收分类** | `category` 驱动验收：内容类走现有自动校验；`ops`/`confidential` 提交时改为「人工验收单」（完成说明 + 通过自检勾选），提交后仍可 reopen 打回 |
| 4 | **通知渠道（P0 命门）** | 邮件 + Webhook（企微/钉钉/飞书）：新任务、接单、超时、审批待办、打回提醒；工程师离线不再=任务超时 |
| 5 | **审计完整性 v1** | task_logs 加 `prev_hash` 哈希链（防篡改可证明）；`GET /api/logs/tasks/:id/audit` 导出单任务治理链路（含 category/rule_id/审批/质量） |

> ✅ **落地状态（2026-08-11）**：阶段一 5 项已全部落地——审批流异步化（`05fedca`）、分级策略引擎 v1（`2f0fefb`）、质量验收分类+一次通过率（`40673b4`）、通知渠道+审计哈希链（`dcc7a05`）。阶段二/三待规划。

### 阶段二 · 治理产品化（3-12 月）

- **治理配置后台**：可视化配置分类规则、审批人策略、质量验收标准、通知渠道
- **治理 dashboard**：分级分布、审批时效、一次通过率、超时率、审计查询
- **多租户 + 租户级治理**：每租户独立分类/审批/质量/SLA 策略（私有部署核心）
- **合规报告**：一键导出「数据不出网关」合规证明（哪些任务被分级保护、无 AI 兜底、审批与审计完整）
- **工程师治理**：一次通过率评级、技能标签、on-call 值班表
- **SLA 分级 + 升级序列**：任务级 SLA，超时按 escalation 逐级通知

### 阶段三 · 治理网络化（1 年+）

- **策略智能漂移**：AI 能力基准动态评估 → general 池边界自动调整；confidential/ops 由制度锁死不漂移
- **治理 API 开放**：上游可查分级决策理由（rule_id/命中规则）、审批链状态、质量验收结果
- **外部生态接入**：治理策略成为可复用服务，对接外部 Agent / 调度平台
- **质量数据资产**：合规前提下用人工产出反哺私有评测集 / 精调

## 四、验收标准（怎么算「做好治理层」）

1. **涉密/运维类任务 AI 兜底率 = 0**（分级白名单制度保障，非人工自觉）
2. **AI 提审批不再阻塞**（异步化 + 回查，与任务契约一致）
3. **一次通过率 / 平均响应时长 / 超时率可度量并持续改善**
4. **任意任务可一键导出完整治理链路**（创建→分级→审批→质量→交付，哈希链可证明未被篡改）
5. **上游零代码接入 + 治理能力可配置**（不靠改代码调整策略）

---

## 五、立即启动项（下一步，按优先级）

1. **审批流异步化**（消除 5 分钟挂起，治理契约统一）—— P0
2. **分级策略引擎 v1**（规则可配置 + 白名单锁死不可降级）
3. **质量验收分类**（内容类自动 / 运维类人工验收单 + 一次通过率）
4. **通知渠道**（邮件 + Webhook）
5. **审计完整性 v1**（哈希链 + 治理链路导出）
