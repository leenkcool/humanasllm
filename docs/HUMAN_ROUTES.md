# 人工路由场景分级（Human Route Category）

> P390 的核心能力是把**必须由人来做**的任务接入多模型 Agent 调度体系。本文件沉淀：什么任务该走人工、按什么标准判断、系统如何分级承载（`category`）、上游如何标记。

---

## 一、判断标准（命中任意一条即适合人工路由）

| 标准 | 说明 |
|------|------|
| **涉密 / 私有** | 数据不能交给公有大模型（出境风险 / 泄露风险） |
| **需人工判断 / 责任归属** | 结果要有人负责，AI 错了无人担责 |
| **物理世界 / 线下操作** | 机器够不到，必须人上手（机房、网络、电力） |
| **合规 / 留痕** | 操作要审计、要审批链 |
| **质量门槛高** | 产出直接进生产，AI 兜底不达标 |

---

## 二、场景清单

### 运维与基础设施（实体 / 涉密，最契合 → `ops`）
- **数据库集中管理**：DDL 变更、迁移、备份恢复、慢查询 / 死锁治理
- **公有云管理操作**：开通 / 扩容 / 降配、权限变更、账单与费用治理
- **网络 / 硬件**：布线、设备上架下架、固件升级
- **机房实体运维**：温度、湿度、防火、电力抢修等（AI 无法代劳的物理世界操作）

### 安全与应急（→ `confidential`）
- 生产事故应急（on-call 处置、根因定位）
- 漏洞修复方案决策（授权范围内）
- 敏感数据导出审批、脱敏策略制定

### 审批型（走 P390 approvals 流，AI 提申请 → 人批/驳 → 回传资源）
- AI 请求数据库只读 / 写权限
- AI 请求开通服务器 / 测试环境
- AI 请求访问私有数据接口

### 业务与内容（→ `general`，可走 AI 兜底）
- 商务 / 合同条款审查
- 需审美判断的产出（品牌文案、UI 终稿）
- 对外发布内容的终审

### 数据类（→ `confidential`）
- 涉密数据标注 / 清洗（不上公网）
- 高价值语料整理，产出直接喂下游

## 三、系统落地机制（`category` 分级）

系统在 `tasks` 表新增 `category` 字段，上游请求可标记任务场景，类别驱动超时兜底策略。

### 分类枚举

| category | 含义 | AI 兜底 | 场景示例 |
|---|---|---|---|
| `general` | 常规（默认） | ✅ 允许 | 内容产出、常规开发、业务数据 |
| `confidential` | 涉密 / 敏感 | ❌ **禁止** | 涉密数据、安全应急、权限审批 |
| `ops` | 运维 / 基础设施 | ❌ **禁止** | 数据库管理、公有云操作、机房实体运维 |

### 行为差异（queueService.timeoutTask）

- **`general`**：待接单超时无人接单 → 自动 AI 代答兜底（原行为不变）。
- **`confidential` / `ops`**：待接单超时 → **直接回落 `returned`**，不触发 AI 代答。涉密/运维上下文**不出网关**，杜绝泄密与误操作。日志以 `task:timeout` 推送并标注，可人工改上下文重派。

> 设计初衷：P390 的存在意义就是把涉密/私有逻辑留在体系内。若让涉密任务超时后自动喂给公有大模型兜底，等于把最敏感的数据送出网关，违背第一性目标。

### 上游接入（OpenAI 兼容请求体）

在 `/v1/chat/completions` 请求体顶层加 `category` 字段即可（无需改代码）：

```json
{
  "model": "human-llm",
  "messages": [{ "role": "user", "content": "对数据库执行 XX 迁移方案，需人工执行" }],
  "category": "ops"
}
```

- 非法 / 缺省值自动回退 `general`，不报错。
- 与已有扩展字段 `priority` / `project_code` / `meta_tags` 并列，全量透传并落库。
- 工作台任务列表 / 详情显示类别标签（涉密=紫、运维=蓝），工程师接单前即可识别。

## 四、与既有机制配合

| 机制 | 配合方式 |
|---|---|
| **审批流** `/v1/approvals` | AI 提资源/权限申请 → 人类批准并提供资源 → 结果回传。云权限、DB 权限类场景直接套用 |
| **超时配置** `TASK_PENDING/PROCESSING_TIMEOUT_MIN` | 涉密/运维类建议调大超时，给人工留足时间（不依赖 AI 兜底） |
| **质量校验** `qualityCheck` | 内容类产出保持现有空/过短/占位拦截；运维指令类建议人工验收，不依赖自动校验 |
| **审计留痕** | `task_logs` / `request_logs` / CSV 导出（含 `category` 列）完整记录任务来源与分级 |

---

## 五、反向：什么**不该**走人工

- 常规编码、快速实现 → 应走 AI（`deepseek-v4-flash` 中继）
- 非涉密、无责任归属风险的批量任务 → 走 AI 更经济
- 可公开、可自动化的确定性操作 → 走 AI / 脚本

人工路由是**最后手段**，仅当命中第一节任一标准时才启用，保持人机调度池的性价比。
