# 人工路由场景分级（Human Route Category）

> P390 的核心能力是把**必须由人来做**的任务接入多模型 Agent 调度体系。本文件沉淀：什么任务该走人工、按什么标准判断、系统如何分级承载（`category`）、上游如何标记。

---

## 一、判断标准（命中任意一条即适合人工路由）

| 标准 | 说明 |
|------|------|
| **涉密 / 私有** | 数据不能交给公有大模型（出境风险 / 泄露风险） |
| **需人工判断 / 责任归属** | 结果要有人负责，AI 错了无人担责 |
| **物理世界 / 线下操作** | 机器够不到，必须人上手（机房、网络、电力） |
| **合规 / 留痕** | 操作要审计、要审批链 |
| **质量门槛高** | 产出直接进生产，AI 兜底不达标 |

---

## 二、场景清单

### 运维 & 平台部门（八大类 → 主要 `ops`，合规安全类 `confidential`）

P390 人工路由的典型承接对象。**平台部负责架构搭建，运维部负责落地执行**；其中涉密 / 合规 / 物理 / 责任类工作归 `confidential` / `ops`，禁 AI 兜底、上下文不出网关。

**权责区分**

| 部门 | 负责 |
|---|---|
| **平台部** | 架构、中间件、容器集群、网关、AI 平台、发布流水线、底层基础平台搭建 |
| **运维部** | 服务器、故障排查、备案合规、渗透安全、日常巡检、上线部署、应急处理 |

**一、服务器 / 底层基础设施**（`ops`）
云服务器、物理机、ARM 主机、Docker/K8s 容器集群、k8s、网关（Nginx/Traefik/Haproxy）部署维护；WSL / Windows-Linux 环境、多网卡路由、DNS、内网网络、防火墙、负载均衡管理；存储 / SSD/HDD / 磁盘阵列、定时快照、数据备份、异地备份；机房、带宽、公网 IP、端口管理、内网权限、SSH 远程访问管控

**二、平台架构与中间件**（`ops`，平台部核心）
数据库（MySQL / Redis / 消息队列 / 对象存储 / 反向代理 / NEW-API 网关）部署运维；微服务项目环境、多项目实例启停、批量脚本、Windows Terminal 批处理脚本维护；前端部署环境、CI/CD 自动发布、版本更新、开发 / 测试 / 预发 / 生产环境区分；私有用户登录系统（Casdoor / Logto）、统一网关、Agent 智能代理平台运维

**三、互联网合规 / 备案 / 安全**（`confidential`，运维主导）
ICP 网站备案、公安网安备案、微信小程序备案；等保测评、等保三级建设、年度复测、通保（通信网络安全防护）备案；渗透测试、漏洞扫描 / 修复、主机基线、权限加固；攻击溯源、入侵排查、应急响应、日志审计、服务器安全巡检；生成式 AI 大模型备案、算法备案、数据安全备案、隐私合规配置；SSL 证书、HTTPS、域名解析、域名续费

**四、监控 / 告警 / 日常故障排查**（`ops`）
服务器 CPU / 内存 / 带宽 / 硬盘 / GPU 算力（H100/H200）功耗监控；服务宕机、接口报错、502/401 权限报错、容器异常、SERVFAIL-DNS 故障排查；程序崩溃、内存报错、定时日志收集、慢请求、接口延迟 P95 优化

**五、账号 / 权限 / 环境 / 项目资源管理**（`confidential`）
服务器账号、管理员密码、密钥、SSH 密钥、后台系统权限管控；多项目（P 系列）目录管理、环境隔离、项目启停、批量运维脚本维护；第三方模型密钥、API 网关令牌、后端服务密钥保管

**六、上线 / 发布 / 迭代**（`ops`）
前后端项目部署、小程序服务端环境、小游戏后端环境搭建；新版本灰度发布、回滚、定时任务 / 定时脚本 / 定时重启服务；环境依赖管理、Chocolatey、软件包版本管控、运行时环境搭建

**七、专项平台类**（`ops`）
AI-Agent 网关、多模型调度、模型接口负载均衡、token 流量统计；私有知识库、向量数据库、Embedding 服务运维；防火墙 WAF、访问黑名单、接口限流、防爬虫、流量管控

**八、日常行政 / 运维琐事**（`ops`）
服务器费用、云服务器账单、算力硬件成本核算；定时备份、定期巡检、安全周报、平台运行报告；开发人员环境支持、外网端口开通、内网互通配置

### 安全与应急（→ `confidential`）
- 生产事故应急（on-call 处置、根因定位）
- 漏洞修复方案决策（授权范围内）
- 敏感数据导出审批、脱敏策略制定

### 审批型（走 P390 approvals 流，AI 提申请 → 人批/驳 → 回传资源）
- AI 请求数据库只读 / 写权限
- AI 请求开通服务器 / 测试环境
- AI 请求访问私有数据接口

### 业务与内容（→ `general`，可走 AI 兜底）
- 商务 / 合同条款审查
- 需审美判断的产出（品牌文案、UI 终稿）
- 对外发布内容的终审

### 数据类（→ `confidential`）
- 涉密数据标注 / 清洗（不上公网）
- 高价值语料整理，产出直接喂下游

## 三、系统落地机制（`category` 分级）

系统在 `tasks` 表新增 `category` 字段，上游请求可标记任务场景，类别驱动超时兜底策略。

### 分类枚举

| category | 含义 | AI 兜底 | 场景示例 |
|---|---|---|---|
| `general` | 常规（默认） | ✅ 允许 | 内容产出、常规开发、业务数据 |
| `confidential` | 涉密 / 敏感 | ❌ **禁止** | 涉密数据、安全应急、权限审批 |
| `ops` | 运维 / 基础设施 | ❌ **禁止** | 运维&平台八大类（服务器 / 中间件 / 备案合规 / 安全 / 上线等，见上） |

### 行为差异（queueService.timeoutTask）

- **`general`**：待接单超时无人接单 → 自动 AI 代答兜底（原行为不变）。
- **`confidential` / `ops`**：待接单超时 → **直接回落 `returned`**，不触发 AI 代答。涉密/运维上下文**不出网关**，杜绝泄密与误操作。日志以 `task:timeout` 推送并标注，可人工改上下文重派。

> 设计初衷：P390 的存在意义就是把涉密/私有逻辑留在体系内。若让涉密任务超时后自动喂给公有大模型兜底，等于把最敏感的数据送出网关，违背第一性目标。

### 上游接入（OpenAI 兼容请求体）

在 `/v1/chat/completions` 请求体顶层加 `category` 字段即可（无需改代码）：

```json
{
  "model": "human-llm",
  "messages": [{ "role": "user", "content": "对数据库执行 XX 迁移方案，需人工执行" }],
  "category": "ops"
}
```

- 非法 / 缺省值自动回退 `general`，不报错。
- 与已有扩展字段 `priority` / `project_code` / `meta_tags` 并列，全量透传并落库。
- 工作台任务列表 / 详情显示类别标签（涉密=紫、运维=蓝），工程师接单前即可识别。

### 上游跟进契约（task_id）

`human-llm` 任务为**异步受理**：`POST /v1/chat/completions` 创建任务后立即返回 `task_id` + `status: "pending"`，不阻塞等待人工完成（人工是**小时级**节奏，AI 是分钟级）。任何上游 Agent / vibe coding 工具必须遵守以下契约，否则任务结果会被遗忘：

1. **提交** → 拿到 `task_id`。
2. **登记未完成**：把 `task_id` 记入自己的未完成清单（防遗忘的关键一步）。
3. **回查**：下次做与之相关工作前，`GET /v1/tasks/:id` 查询处理结果。
4. **交付 / 轮候**：
   - `status: completed` → 取 `content`（人工产出）交付，任务结清。
   - `status: returned` → 转达驳回原因，补充上下文后可重新派单。
   - `status: pending|processing|paused` → 如实反馈状态，**继续轮候**直到完成。

**Claude Code 侧自动实现**：`humanllm` 子代理（`.claude/agents/humanllm.md`）+ `dispatch-human` skill 已按本契约工作——提交后把 `task_id` 登记到 `data/human_followup.json`，每次被调用先回查，完成即交付产出、未完成反馈状态继续轮候。

## 四、与既有机制配合

| 机制 | 配合方式 |
|---|---|
| **审批流** `/v1/approvals` | AI 提资源/权限申请 → 人类批准并提供资源 → 结果回传。云权限、DB 权限类场景直接套用 |
| **超时配置** `TASK_PENDING/PROCESSING_TIMEOUT_MIN` | 涉密/运维类建议调大超时，给人工留足时间（不依赖 AI 兜底） |
| **质量校验** `qualityCheck` | 内容类产出保持现有空/过短/占位拦截；运维指令类建议人工验收，不依赖自动校验 |
| **审计留痕** | `task_logs` / `request_logs` / CSV 导出（含 `category` 列）完整记录任务来源与分级 |

## 五、反向：什么**不该**走人工

- 常规编码、快速实现 → 应走 AI（`deepseek-v4-flash` 中继）
- 非涉密、无责任归属风险的批量任务 → 走 AI 更经济
- 可公开、可自动化的确定性操作 → 走 AI / 脚本

人工路由是**最后手段**，仅当命中第一节任一标准时才启用，保持人机调度池的性价比。
